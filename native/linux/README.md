# Treadory Linux 0.3.0 experimental preview

Standalone Python/Tk configuration with evdev pedal isolation and uinput actions; no Chrome extension/helper. The dependency-declaring `.deb` contains runnable scripts, not a bundled Python runtime. It is architecture-independent source; actual Linux runtime/GUI/OS integration and physical compatibility remain verification gates. Do not advertise validated CPU support until a target runner passes. Runtime dependencies: Python 3.10+, Tk, python-evdev (BSD), python-dbus (MIT), PyGObject, systemd-logind and a loaded uinput kernel module. Use distribution packages; nothing is fetched at runtime.

Install the preview deb using your distribution's normal package installer, which resolves dependencies. Installation needs administrator access but never starts capture. Launch Treadory from Applications. Never run its GUI as root. Grant narrowly scoped read/write access to the **verified pedal event node** and `/dev/uinput` with an administrator-reviewed udev rule for a dedicated local group. Example (review group name and actual sysfs attributes first):

```udev
SUBSYSTEM=="input", KERNEL=="event*", ATTRS{idVendor}=="05f3", ATTRS{idProduct}=="00ff", GROUP="treadory", MODE="0660"
KERNEL=="uinput", SUBSYSTEM=="misc", GROUP="treadory", MODE="0660"
```

These grants allow input capture and virtual input; limit group membership. Do not use `chmod 666` or broadly join `input`. Rule installation, group creation/membership, udev reload/replug and login renewal are administrator steps that Treadory does not execute automatically. Confirm that the rule matches USB ancestry on your device. A missing permission or logind session fails safely with a visible error. Permission revocation may not invalidate already-open file descriptors immediately: stop/quit before revoking access.

Connect a pedal, Inspect, review recovery, release all pedals and Start isolated test. Only one `05f3:00ff` event node advertising exactly left/right/middle buttons and no pointer axes or other keys is eligible. Composite/ambiguous/unsupported nodes are refused. This may exclude a real Infinity device; an unsupported pedal is not a defective pedal. evdev metadata establishes node identity, not the cause of another remapper's injected click. Stop other remappers and compare outside the browser first.

Learn each pedal with a full press/release. Verify suppressed original outputs in another app and ordinary-mouse operation. Save mappings while isolated or paused, then verify and Activate explicitly. Settings are under `$XDG_CONFIG_HOME/treadory/settings.json` or `~/.config/treadory/settings.json`. Only mappings persist; device selection, learning and activation do not. Supported actions: wheel scroll, media play/pause and Space/Enter/F13–F24 taps. Compositor focus, media-key routing and existing physical keyboard modifiers can affect delivery. Seeking needs a player-specific binding/integration; there is no universal rewind. This version does not expose arbitrary shortcuts or shell commands. Separate virtual key and scroll devices avoid misclassifying a wheel-only hybrid as a keyboard. The scroll device advertises pointer axes/buttons for [udev classification](https://github.com/systemd/systemd/blob/main/src/udev/udev-builtin-input_id.c); Treadory emits only wheel events on it, never pointer movement or button presses. Actual compositor classification and delivery remain manual release gates.

**OS 250 ms click guard is unavailable.** The UI says so. Device-specific pedal suppression still works where EVIOCGRAB succeeds; ordinary mice are never grabbed. A Wayland-compatible broad guard would require continuous forwarding of grabbed ordinary-mouse streams through uinput, complete sequence/state handling and independently validated watchdog/crash behavior. No X11/page-only workaround is described as OS protection. See the platform matrix. That component remains an implementation blocker.

Pause stops configured actions and retains the pedal grab. Stop or quit releases it. A separate worker owns input; UI heartbeat loss after five seconds, node identity changes, session lock/inactivity/sleep via systemd-logind, overflow or input/action failures release capture or exit the worker. Stop before sleep/lock until desktop behavior is physically validated. Worker failure requires restarting the app; it never silently resumes capture. The process reads only the selected pedal, not ordinary keyboard/mouse streams. Normal exit and kernel file closure release EVIOCGRAB; crash/kill tests remain a real-OS gate.

Emergency: Stop capture; Ctrl+Alt+Shift+F12 while the Treadory window is focused; unplug the pedal or terminate Treadory with the desktop process manager from another app. A computer-wide emergency chord is not implemented. Ordinary mice/keyboards remain available. Remove the package through the normal package manager, delete settings if desired, remove the dedicated udev rules/group grants and reload/replug as instructed by your administrator. No auto-start, service, native listener or telemetry is installed.

Creator: Ronit Gandotra. Build the real `.deb` with `python3 scripts/package-platforms.py linux`. Pure policy tests can run on any OS; Linux runner installation, Xvfb GUI, uinput/evdev and X11/Wayland tests are distinct from physical verification. No signing credentials are bundled; package repository signing is a release task.
