# Treadory macOS 0.3.0 arm64 developer preview

This is a real AppKit application, independent of Chrome. Only arm64 is built; macOS 14 or later is the declared deployment target. Intel is not distributed. GUI startup and pure policy tests ran on the macOS build host. No physical pedal, exclusive-access or event-tap permission tests have run. Do not treat this preview as verified IN-USB-3 compatibility.

Extract `Treadory-0.3.0-macos-arm64-preview.zip` and move Treadory.app into Applications. This build has ad-hoc signing only, no Developer ID or notarization. Public release requires those credentials and clean-machine Gatekeeper checks. Do not disable system security to install it. macOS frameworks supply the runtime; no driver, browser or native helper is required.

1. Open Treadory. No capture starts automatically.
2. Use Permissions to request Input Monitoring and Accessibility in System Settings. Reopen if macOS requires it. Input Monitoring is checked before discovery; Accessibility is checked before actions.
3. Connect a VEC pedal and Inspect. Exactly one matching `05f3:00ff` HID service with a two-byte input report is eligible. The app shows name, identity and candidate status. Multiple services, identical pedals, composite devices and other report formats are refused. This deliberately narrow eligibility may exclude the affected device.
4. Review recovery, release all buttons, then Start isolated test. Exclusive IOHID access must succeed. Press/release once to establish neutral, then learn each physical pedal. Check in another app that originals are suppressed and an ordinary mouse still works. Software learning does not reprogram firmware.
5. Choose/save actions and guard scope while isolated or paused. Mappings and guard preference persist in `~/Library/Application Support/Treadory/settings.json`; identity, learning and active capture do not. Explicitly Activate after verification.
6. Scroll uses Quartz line events, subject to macOS focus/pointer scrolling behavior. Space/Enter/F13–F20 are supported key taps for applications that bind them. This version has no native media integration or universal rewind; use a player-supported shortcut. Physical keyboard modifiers can affect key taps.
7. Pause clears the guard and stops actions while retaining exclusive pedal access. Stop or quit closes HID access and restores original input. Sleep/session notifications, permission loss, topology changes, invalid reports and a five-second UI heartbeat loss stop capture. No automatic reconnect/activation.

Optional timing guard: off by default; all buttons (left, middle, right and additional Quartz mouse buttons) or right only. It starts at decoded press detection, lasts until detection + 250 ms, and runs before configured actions. Repeated physical press edges update the deadline; held-report repeats do not. It cannot identify the source of an ordinary click. Legitimate ordinary-mouse clicks can be lost. Movement/wheel and tagged Treadory actions are excluded. A preexisting drag can finish. A canceled press owns its release for up to five seconds, then fails open; pause/stop clears sequence tracking immediately. This is a documented exception to blocking every release during the window, to avoid stuck dragging. Secure/login desktops, low-level HID consumers, earlier events and disabled/refused taps are not covered. Timeout/user-disabled taps stop capture; they are not silently re-enabled.

Emergency stop: Control + Option + Shift + F12 on the normal session, Stop capture, quit, unplug the pedal or terminate Treadory with Activity Monitor. Process exit closes OS handles; actual crash recovery and tap/HID cleanup need hardware testing. To uninstall, stop/quit, remove Treadory.app, delete its Application Support/Treadory settings folder if desired, and revoke its permissions. No launch agent or service is installed.

No telemetry, network listener, page/history collection, ordinary input recording or shell actions. Temporary mouse button state is kept only for guard sequence pairing. Creator: Ronit Gandotra.

Build: `python3 scripts/package-platforms.py macos`; this invokes swiftc with the arm64 macOS 14 target, compiles the actual source, runs policy tests, packages the app and records source/artifact checksums. A GUI check is separate: app executable `--ui-test` never activates capture. Rebuild before shipping any source edit.
