Treadory tests and maps supported USB foot pedals. Browser USB input
requires a WebHID-capable desktop browser and explicit device permission.
Website and Chrome extension settings are stored separately and locally.
No account, analytics or telemetry is provided by Treadory.

Website-wide mode uses the Chrome extension on permitted website tabs.
It does not suppress original operating-system clicks or control desktop apps.

System-wide mode uses the standalone Treadory.exe Windows x64 developer preview.
It has its own settings and does not require Chrome or an extension. The one-file
portable EXE includes the .NET runtime; no ZIP or helper registration is needed.
Original-output replacement still requires a separately obtained, appropriately
licensed Interception driver and verified x64 DLL. Neither is redistributed.
Only one uniquely identified eligible VEC mouse endpoint can be captured;
ordinary mice are excluded. Physical Windows/pedal verification is pending.
A macOS arm64 app ZIP is an ad-hoc-signed, unnotarized preview with GUI startup checks only; physical HID/tap behavior is unverified. A Linux experimental deb remains a maintainer artifact pending runtime checks; its OS click guard is unavailable. Production signing/installation and physical input tests remain gates.

Learning maps physical controls in software; it does not reset or program
pedal firmware. Stop capture or disconnect to restore original pedal input.
The recovery chord is Ctrl + Alt + Shift + F12. Elevated apps and secure
desktops are excluded. Follow the package README for setup and removal.

Optional Windows/macOS OS and extension page guards block new mouse presses for 250 ms after decoded physical pedal detection. Users explicitly select All buttons or Right only; ordinary-mouse clicks can also be lost. Movement/scrolling remain available; release sequence ownership is bounded to five seconds. No guard identifies click-source devices.
