## Input path

Windows standalone: explicit metadata inspection → uniquely matching driver endpoint → explicit isolated capture → three-button state decoding/edge detection → selected originals consumed → optional hook deadline armed **before action execution** → whitelisted SendInput taps/wheel → pause clears guard and actions but retains selected isolation → stop/identity/desktop/heartbeat/failure releases context and learning. Other mice bypass driver capture. Hook cancellations are timing-based, with no source identity; tagged own input is excluded. The app still requires the eligible driver source even if only timing protection is desired.

Extension: authorized unique WebHID device → known profile or explicit calibration → neutral/release gating → physical down edge → permitted active-page guard injection and independent action routing → DOM actions / tab operations → pause/setup/navigation/permission removal/disconnect clears guards. All permitted frames are attempted; inaccessible frames may prevent coverage. Synthetic actions stay usable. Protected pages/Chrome UI/other apps are excluded. The website's standard-key/mouse learning mode does not become a physical-device OS interceptor.

Historical helper: authenticated native-messaging packets → same selected endpoint engine → whitelisted system actions → heartbeat/port/session recovery. Retained only as historical development material; current extension cannot connectNative and has no nativeMessaging permission or helper assets.

macOS prototype: explicit Input Monitoring → one eligible HID service → explicit exclusive open → validated two-byte neutral/press decoder and session-only learning → optional session tap deadline → configured Quartz wheel/key events → pause/tap removal → stop/permission/topology/session/heartbeat closes exclusive access. Candidate decoding does not establish the actual Infinity descriptor or effective suppression.

Linux prototype: sysfs identity/readable capabilities → unique button-only VEC node → explicit EVIOCGRAB plus separate uinput output → complete learned physical edges, ignoring repeat → whitelisted taps/wheel → stop/worker exit closes grab. Ordinary mice are never read/grabbed. No OS timing guard is implemented. systemd-logind is required; normal-session, sleep and heartbeat checks are separate from GUI packaging.

## Guard behavior and races

New down events are eligible during `[detection, detection + 250 ms)`. Releases follow their own down ownership. Canceled sequences remain canceled for at most five seconds; this may extend release cancellation past 250 ms, but never extends eligibility for **new** clicks. An existing ordinary drag can complete. Disabling/pausing/stopping/navigation clears protection immediately; a late orphan up may then reach a page, and a website with an up-only handler can react. No input is delayed/replayed. After the failsafe an unusually long canceled hold's release may pass. These choices avoid indefinitely retained blocking/state, and must be physically tested.

Windows/macOS ordinary mouse clicks in scope may be lost, including external injected clicks; markers exempt only own actions and do not identify the pedal source. Extension guard allows untrusted programmatic events so configured clicks are preserved. Keyboard context menus with nonmouse button identity pass. A trusted contextmenu with no observed down also passes to preserve preexisting/keyboard sequences; there is no claim of unconditional context-menu suppression.

The extension uses `performance.timeOrigin + performance.now()` to transport the detection deadline across contexts, and local monotonic elapsed decisions. Windows uses TickCount64; macOS uses system uptime. Repeated press edges update deadlines; held reports do not. An older/expired extension arm request cannot shorten or remove a newer window. Scheduling, permissions, navigation and earlier page capture listeners remain races. No later cancellation can undo an executed website handler/default action. Timing correlation is never used to assign the right-click's cause.
