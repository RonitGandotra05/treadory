## Remaining release gates

1. Establish the right-click source on the affected computer. Quit other remapping/transcription utilities and compare behavior outside Treadory. Inspect the real endpoint metadata. No matching mouse endpoint means this backend is not an established fix.
2. Confirm applicable Interception commercial licensing and driver support on the exact Windows version/security configuration. Windows 11, HVCI, Secure Boot and ARM64 compatibility are not established by the project's documented Windows XP–10 testing. ARM64 is refused by this preview.
3. On supported Windows x64 hardware, prove all original selected-pedal outputs are suppressed in native apps and browsers while simultaneous ordinary mouse input remains normal. Confirm other utilities do not independently inject clicks. Test all three controls, holds, chords and repeats.
4. Verify filter restoration for Stop, disconnect, helper/browser crash, lease expiry, unplug/replug, duplicate pedals, lock/unlock and sleep/wake. Verify no stuck inputs and the emergency chord. Portable lifecycle tests cannot establish driver crash cleanup.
5. Run clean-machine installer/uninstaller and Chrome/Edge/Brave native messaging tests. Establish signing and a production installer; measure resource use and action latency. Elevated apps and secure desktops remain outside the initial scope.

See [the sourced architecture decision](INPUT-ARCHITECTURE.md) and [setup/recovery instructions](../native/windows/README.md). Mac and Linux backends are not implemented or offered as downloads.

## 0.3.0 app / 0.1.9 extension manual release checklist

Keep separate records for unit/mock, real-browser, OS API, GUI/install and physical tests. Record OS build/CPU, driver/security configuration, descriptor/node identity, permission state, utilities running, app/extension version and checksums. Do not share serials or private mappings publicly.

- Establish the affected IN-USB-3 cause: compare with all remappers stopped, another app/browser and another computer; observe each USB collection. Never infer a click's source solely from a 250 ms correlation.
- At each platform, inspect unsupported, two identical, composite, replaced and replugged devices. No ambiguous device may be captured; no reconnect/startup/installer may activate it. Read denied identity is an error, not absence. Confirm local settings migration keeps guard Off or legacy Right only; learning/active identities must not survive a new capture.
- For each pedal, learn press/release, simultaneous chords, repeated edges and a ten-second hold. Verify originals are consumed during isolated/paused capture and only the configured action reaches focused normal editor/browser/player. Test scroll routing with pointer over another window; test supported player bindings for seeking. No generic rewind claim.
- With a separate ordinary mouse, verify left/middle/right/X1/X2 (and macOS page-supported additional buttons), double-click, dragging, wheel and movement. Test guard Off, All and Right; physical keyboard input must remain available. Measure at 0, 249, 250, 251 ms from **decoded detection**, not action completion. Check Do nothing also arms, holds do not extend, repeated physical presses renew, and delayed actions/injection do not extend deadlines.
- Record ordering of physical report arrival, guard arm and mouse-event receipt without claiming source attribution. Test unwanted click before detection, between detection and hook/page installation, and after arming. Already-executed website handlers/defaults cannot be undone. Never delay/replay every ordinary click to conceal this race.
- Sequence tests: down before detection/up during window remains allowed; down at 249/up at 251 stays canceled; down after 250 passes; prior held drag can release; canceled ten-second hold fails open after five seconds. Pause/stop/disable immediately clears; check late up-only website handlers. No stuck buttons/keys after double-click or simultaneous buttons. Treadory's synthetic DOM and tagged native actions remain usable.
- Extension: real installed Chrome with per-origin permission and permitted/unpermitted cross-origin frames; reload/navigation/tab/focus changes and access revocation; protected browser pages and toolbar explicitly excluded. Keyboard context menus preserved; extra-button browser navigation may be outside cancellable page behavior. Store ZIP contains no native-helper files/permissions; publishing website does not publish Store release.
- Windows: current supported OS/security features unchanged, licensed driver install/uninstall/admin/reboot, actual per-device isolation, ordinary mouse independent, hook refused/timeout, UIPI/elevated/secure desktop, user-space hook process kill and driver-context crash recovery. CI synthetic hook test is not pedal/driver proof.
- macOS: Input Monitoring/Accessibility deny/grant/revoke/restart; exclusive access refused by another client; all actual composite HID services; session tap creation and timeout/user disable; sleep/wake/lock/worker/UI freeze/process kill. Only arm64 is built; Intel remains unavailable. Developer ID/notarization/Gatekeeper clean-machine installation gate.
- Linux: dependency installation/desktop launch, narrow udev permissions, ambiguous evdev nodes, actual EVIOCGRAB and uinput routing on X11 and GNOME Wayland, logind lock/sleep/inactive session, descriptor permission revocation (existing open fd may remain usable), GUI freeze/worker SIGKILL and unplug. Windows PE or macOS bundle structure and startup alone do not prove interception. Remove all test processes.
