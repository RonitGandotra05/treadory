# Platform feasibility and implementation decision

Research and source inspection: 10 October 2026. This matrix describes API feasibility, not verified pedal compatibility. The IN-USB-3 label does not identify the source of the reported right-click. No physical pedal is available in this workspace. First compare with other remapping/transcription utilities stopped, outside Chrome and on another computer. Do not reset firmware without a verified manufacturer protocol.

## Primary evidence

- [Raw Input overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input) and [RAWINPUTDEVICE flags](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice): metadata/source attribution is separate from interception. `RIDEV_NOLEGACY` is not a selective global filter.
- [Microsoft mouse hook contract](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc): cancellable messages, dedicated thread, timeout/removal. [Mouse hook structure](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct): injected flags/extra info, no physical device handle. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): UIPI and keyboard-state limitations.
- [Interception README/license](https://github.com/oblitum/Interception): administrator installation, testing through Windows 10 and commercial license terms. [Implementation](https://github.com/oblitum/Interception/blob/master/library/interception.c): context destruction closes handles. This is evidence about library cleanup, not a measured driver crash-recovery guarantee. It is not presented as a maintained modern Windows solution.
- [Apple IOHIDDeviceOpen](https://developer.apple.com/documentation/iokit/1588670-iohiddeviceopen): exclusive access option. [Quartz tap creation](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)): active versus passive filtering and tap location restrictions. [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution): distribution requirements. Actual TCC behavior is a platform test gate.
- [Linux evdev](https://docs.kernel.org/input/input.html), [grab contract](https://www.freedesktop.org/software/libevdev/doc/latest/group__init.html), [uinput](https://kernel.org/doc/html/latest/input/uinput.html): reads, grabs and output are separate. The kernel recommends libevdev over direct uinput ioctls. [python-evdev repository](https://github.com/gvalkov/python-evdev) and [API](https://python-evdev.readthedocs.io/en/latest/apidoc.html) provide maintained bindings (BSD licensing; check package notices). [Wayland model](https://wayland.freedesktop.org/faq): compositor owns input routing.
- [Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting): host-permission and frame boundaries. DOM guards cannot cancel OS input, browser UI or handlers already executed.

## Architecture comparison and choice

Keep React for the website and extension. Keep the native WinForms app and its isolation backend rather than introducing an Electron/Tauri wrapper. [Electron native integrations](https://www.electronjs.org/docs/latest/tutorial/native-code-and-electron) and [Tauri architecture](https://v2.tauri.app/concept/architecture/) both require an additional input component; packaging gives neither device isolation nor cancellation. Electron adds a Chromium runtime. Tauri reduces bundled UI runtime but introduces Rust/webview/FFI deployment. Qt adds a runtime and licensing choice. These options do not resolve the input problem. Small platform-native frontends/backends minimize runtime dependencies; duplicated UI maintenance is a conscious tradeoff. No custom kernel driver is planned.

Windows has an existing usable development path, so add the timing guard independently of its device filter. The guard still requires a decoded pedal source: in this preview that source is the eligible Interception endpoint. A hook alone cannot recognize pedal presses. Do not broaden driver capture to all ordinary mice. Preserve original-output suppression even with the timing guard off.

macOS and Linux require separate conservative prototypes, then physical proof before general release. Reject ambiguous identities and unsupported collections rather than guessing pedal buttons. Linux broad timing protection is an explicit unimplemented capability until ordinary-mouse forwarding, lock/sleep and crash recovery are proven; never call page protection equivalent. No universal rewind: configure a supported application shortcut; media integrations differ. Software mapping does not program firmware.

## Proof-of-concept gates

Measure detection versus unwanted-click arrival, permission failures, seize/grab behavior, composite endpoints, unplug/replug, worker/UI stalls and crash cleanup on each target OS. For Windows, test the actual licensed driver with current security features unchanged. For macOS, test session tap creation as a normal user and permission revocation. For Linux, test evdev/uinput on both GNOME Wayland and X11, including virtual-device recognition and session lock. No downloadable artifact or green unit test substitutes for these tests.
