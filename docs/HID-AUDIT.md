# Treadory device-logic audit — 8 October 2026

> Historical audit of the input-only app. A later, explicitly requested device programming flow is documented in [DEVICE-PROGRAMMING.md](DEVICE-PROGRAMMING.md); its output writes and added UI were introduced after this audit.

This pass inspects the existing implementation first and compares actual source, not just project descriptions. No reference code is executed or incorporated. The UI, CSS, pedal artwork, and static frontend architecture are outside the change scope.

## Comparison recorded before implementation

| Subsystem / finding | Classification | Decision and evidence |
| --- | --- | --- |
| Infinity independent bits 1/2/4 at payload byte 0 | KEEP OUR APPROACH | Biped uses the same bits and edge detection; Linux references expose equivalent button usages 0x90001–3. Independent tests cover all eight combinations. |
| Report IDs and DataView slices | KEEP OUR APPROACH | WebHID supplies the ID separately, unlike some native buffers. Our byteOffset/byteLength handling is already correct. |
| Known-report validation | IMPROVE OUR APPROACH | Infinity currently accepts any ID and turns malformed packets into releases. Require the documented report ID and length; retain state for rejected packets. A corrupt packet is not a pedal-up event. |
| Generic learning | KEEP OUR APPROACH | Independent changed-bit fingerprints handle nonzero baselines, active-low controls, later bytes, and separate IDs. Reject shared encodings rather than promise simultaneous support. Do not install a universal descriptor parser from firmware. |
| Truncated learned reports | IMPROVE OUR APPROACH | An unexpected length currently becomes a false release. Preserve the affected report's previous state. |
| Partial multi-bit learned patterns | IMPROVE OUR APPROACH | A value matching neither the learned pressed pattern nor its baseline must not manufacture a release. Preserve prior state until either recognized pattern arrives, analogous to retaining state on invalid/rollover packets in HID Remapper. |
| X-keys XK-3 compatibility | ADD MISSING LOGIC | SDK source has pedal bits at native index 3 and timestamps at 19–22. Generic whole-report learning can capture timestamp bits. Add only documented raw-input PID modes, converting the SDK's report-ID-prefixed layout to WebHID payload offsets. Ignore non-button data types. |
| Interface selection | IMPROVE OUR APPROACH | footswitch's June 2026 macOS fix and Micro 2 distinguish configuration interfaces from keyboard/input interfaces. Prefer a uniquely identified readable interface, not blindly the first object. |
| Multiple identical authorized devices | IMPROVE OUR APPROACH | Native paths/serials are unavailable in WebHID. Do not silently restore an arbitrary identical match. Require explicit browser selection if ambiguous; keep one active device. |
| Restore versus explicit connect race | IMPROVE OUR APPROACH | A late getDevices() result can supersede a pending explicit connection. Guard restoration with the connection generation and pending state. |
| Open/close and unplug cleanup | KEEP OUR APPROACH | Our generation guard, serialized lifecycle, source identity check, and synchronous listener removal are stronger than several references. Keep them and extend race tests. |
| Focused DOM fallback | ADD MISSING LOGIC | A held key can stay down after Tab leaves the capture area. Release on capture-area blur, without cancelling an unrelated raw-HID hold. |
| Background HID after focus cleanup | ADD MISSING LOGIC | The release-on-window-blur code can immediately retrigger from the next repeated held report. Suppress background actions and require observed release of held controls before rearming them on return; keep physical input visible separately from action eligibility. |
| Stored fingerprint consistency | IMPROVE OUR APPROACH | A report ID has one fixed layout; reject differing lengths for that ID. Mouse fingerprints need matching button IDs so their releases can be found. Apply the same 512-byte limit to new learning and imports. |
| Simultaneous mouse buttons | ADD MISSING LOGIC | Pointer events only emit pointerdown for the first button and pointerup for the last. Observe buttons changes on pointermove too; keep scoped capture. |
| Action down/up pairing | IMPROVE OUR APPROACH | Mapping edits and disabling preview currently leave unmatched integration presses. Remember the dispatched mapping/source until its release, and flush releases before edits, calibration, or disabling. |
| Diagnostic input isolation | IMPROVE OUR APPROACH | A DOM event can become a raw-HID diagnostic candidate. Only the active source may start/complete a step; optional system events may annotate a hardware candidate. |
| Calibration hold timing | IMPROVE OUR APPROACH | PCsensor once/pulse modes can produce short DOM key/click pairs even while the physical pedal is held. Keep the raw-HID 80 ms check; accept paired DOM pulses without imposing physical hold timing. |
| Debounce and long holds | KEEP OUR APPROACH | Deduplicate identical state reports, retain true holds until release. No source establishes a required Infinity software debounce delay. Avoid introducing arbitrary latency or repeat/long-press actions. |
| HID writes / programming / native injection | NOT APPLICABLE TO WEBHID | Programming is possible on some accessible vendor interfaces, but these are device-specific protocols outside this input-only app. Do not transplant OS injection, drivers, firmware, RPC wake packets, EEPROM writes, or report-ID probing writes. |

The decisions above precede application-source edits. Regression results and exact changes are recorded below after validation.

## Exact implementation changes

- `src/hid/deviceProfiles.ts`: report-aware decode contract, readable-collection matching, strict Infinity report 0/two-byte validation, narrowly matched XK-3 adapter ignoring timestamps and status replies. Existing catalogue/layouts remain.
- `src/hid/useFootPedal.ts`: choose a unique best readable interface; refuse ambiguous automatic restoration; guard late authorized-device lookup with generation/current/pending checks. Existing serialized open/close, stale-open cleanup, chooser permission flow and listener disposal are retained.
- `src/hid/core.ts`: unexpected learned-report lengths and unrecognized partial multi-bit patterns retain prior state; new calibration enforces the same 512-byte bound as imports; imported fingerprints cannot disagree on length for one report ID; DOM IDs must match the key code/modifier signature or mouse button needed for release.
- `src/App.tsx`: rejected reports still reach diagnostics but cannot alter held state or advance a wizard; diagnostics use normalized switch state so timestamps/unit IDs cannot prevent release; DOM inputs cannot start a raw-HID diagnosis; short paired DOM pulses can calibrate. Pointer buttons changes now handle chords, cancellation and lost capture. Leaving the capture area releases its DOM controls. Each emitted down owns a snapshot of its mapping and source; release uses that snapshot, including edits/disabling/disconnect. Background reports do not execute actions, and held controls require an observed release before rearming after focus/mode/reset cleanup; the live inspector continues to show actual physical reports.
- `tests/core.test.ts` and `tests/audit-browser.mjs`: added protocol, persistence and virtual-device regressions. Existing `tests/browser.mjs` retained. `README.md`: compatibility and integration behavior updated. No dependencies were added.

## Deliberately retained / excluded

Infinity independent bit detection, edge deduplication, multi-ID generic state preservation, active-low calibration, atomic calibration saves, source separation, declarative mappings, bounded history, safe imports and the existing lifecycle queue remain. Long holds continue until a real release; there is no arbitrary action-repeat or software debounce delay. Mechanical chatter with actual alternating states still needs hardware evidence before choosing a debounce policy.

No OS input injection, hidraw/hiddev/evdev access, native drivers, Rust/Python service, Electron, firmware runtime, generic HID descriptor rewrite, EEPROM command, RPC wake packet, feature/output write, or blind report-ID probing was copied. Some programming protocols can be implemented directly in WebHID; this app intentionally remains an input reader/app mapper. All new logic is original code derived from protocol facts and reproduced failures, so no reference-library code or licensing obligations were imported.

## Remaining practical limits

- Browser WebHID support, secure origins, permission policy, protected collections, OS access restrictions and exclusive claims by other programs cannot be bypassed by a static page. Requesting a HID chooser must remain a user gesture. See [WebHID specification](https://wicg.github.io/webhid/) and [blocklist](https://github.com/WICG/webhid/blob/main/blocklist.txt).
- DOM input exposes keys/buttons reaching the focused page, not hardware identity. It cannot distinguish a pedal from an ordinary keyboard/mouse, recover events consumed by the OS, inject trusted desktop input, or recover a physical hold from firmware that sends only an instantaneous pulse.
- One raw device is active at a time. WebHID itself permits multiple devices; adding simultaneous device routing is an application extension, not a browser impossibility. VID/PID/name has no serial/path uniqueness, so identical devices share calibration and ambiguous restores require explicit selection.
- Generic learning supports independent stable bit patterns, not every arbitrary protocol. Counters/noise, mutually exclusive encoded values, analog/MIDI/gamepad signals, relative wheel/movement, modifier-only inputs, reserved Tab/Escape and multi-key macro streams are not learned as independent held pedals. Prefer distinct ordinary key codes or button signals for the DOM path. These are explicit support boundaries, not claims that WebHID forbids such adapters.
- Input-only listening cannot infer a dropped release or request an initial state on devices that report only changes. An arbitrary hold timeout would break legitimate long presses; focus loss, disabling mappings and disconnect provide explicit release cleanup. Press/release a control after connection to obtain a report. Protocol-specific query/output commands were intentionally not introduced.
- Physical Infinity/XK-3 hardware and actual browser/OS HID transport still need hardware testing. Virtual tests verify our code and event lifecycle, not firmware descriptors, USB timing or real permissions.
